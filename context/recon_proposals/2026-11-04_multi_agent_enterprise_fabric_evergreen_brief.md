**Decision the reader is facing:** Whether the fabric's request path is a model-driven planner that decides the next step each time, or a deterministic workflow template — a state machine that classifies the request, gathers required fields, runs the validation gates and delegates — with the model invoked only inside one bounded sub-task; and, if it is the template, exactly which steps belong on the code side of that cut. It bites at the first change request, when a new workflow has to ship without new agent code, and again when the same workflow runs at batch scale rather than one item at a time.

**Thesis:** The reliability of an enterprise agent fabric is bought by how much of the request path is code, not by how capable the model in it is: a deterministic blueprint beat the strongest agent baseline by 97.6% on TravelPlanner (35.56% against 18.00%) with 96% fewer constraint violations and 27.1% fewer steps, Meta's production orchestrator keeps six of seven steps deterministic and took per-column configuration prep from three to four days to under an hour, and an isolated orchestrator-worker design held 65.3% where a single agent collapsed to 16.6% at 80-task batches — while the same paper concedes the advantage is proportional to how procedurally well-defined the workflow is, so the decision is never "model or code" but which steps are knowable in advance.
