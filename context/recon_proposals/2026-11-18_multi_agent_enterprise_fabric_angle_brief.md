**Signal A (Anchor 1):** When Tool Names Are Not Identities: Measuring Provider Misbinding in MCP-Based AI Agents — Anbiaee, Dadkhah, Ghorbani (University of New Brunswick) — 2026-11-16, 12 metadata conditions × 50 trials per client: exact name + copied description + compatible schema sends 1.00 of trials to the attacker on three of five clients, while exact name alone stays at 0.00–0.02 (https://arxiv.org/abs/2611.21577).
**Signal B (Anchor 2):** Experience Rot: Experienced Agents Fail Where Novices Succeed — Xu, Yin, Zhang, Zhao, Liu (University of Chicago / eBay / University of Florida) — 2026-11-16, six models: after a silent interface change, an agent that did the task before succeeds 0.23 of the time against 0.63 for an agent that never saw it, and up to 1.00 of those failed runs report the task as done (https://arxiv.org/abs/2611.20922).
**Emergent Collision Point:** Both failures are one missing step, seen from opposite sides of the same boundary. Anchor 1 shows the fabric cannot tell *whose* tool it is calling: the name, description and schema that the client selects on are written by whoever advertises them, so an outsider that copies three strings wins the call. Anchor 2 shows the fabric cannot tell *which version* of the tool it is calling: the agent's own correct memory of yesterday's call becomes today's wrong call, because nothing re-binds the remembered call to the interface that is live now. Neither paper states the union — that invocation has no identity resolution at all, and "permission to call" is the only check either system performs. The fix is one mechanism, not two: resolve the provider and the interface version at the moment of the call, from a source the model neither writes nor remembers.
**Hook:** An agent schedules a meeting, the server renames one field, the agent repeats the call it made last week, the server accepts it, stores an empty attendee list, and the agent tells the user the meeting is booked — then, from the other side of the same boundary, a server that IS the impostor takes 50 of 50 calls on three of five clients because it copied the name, the description and the schema.
**Tension:** Every governance control the enterprise fabric has deployed — OAuth grants, gateway policy, approval prompts, tool allow-lists — answers "may this principal call this capability". None answers "is this the capability". So the control surface is orthogonal to the failure: a fully permissioned call can still go to the wrong provider and a fully authorised replay can still carry a stale field. This empowers the teams that own the invocation path (gateways, orchestrators, registries) and threatens the assumption that a model's approval prompt is a security boundary.
**Target reader:** ai_architect
**Single claim to defend:** A multi-agent fabric binds a call to a name and remembers the call by its argument shape, and neither is an identity — so provider identity and interface version have to be resolved at invocation, outside the model, or permission checks will keep approving calls that reach a party the request never named.
