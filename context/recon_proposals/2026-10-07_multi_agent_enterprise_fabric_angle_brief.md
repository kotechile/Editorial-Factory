# Angle Brief: multi_agent_enterprise_fabric — 2026-10-07

**Angle Type:** Synthesis (Cross-Topic Fusion)
**Winner:** Durable Execution Isn't a Transaction: Who Tracks the State the Tool Contract Can't Describe?
**Scores:** E=9 A=9 S=9 → Composite=9.0

**Signal A (Anchor 1):** *Tracking State Footprints: How Agents Can Transact* (Mraz, Şerban, Psarakis, Kulahcioglu Ozkan, Katsifodimos; Delft University of Technology + Ververica; submitted 2026-10-02 as arXiv:2610.03140, cs.DB; PVLDB 20(1)) — "most of today's orchestrators track *control flow* … but not *data flow*, i.e., which state each task reads and writes," so "concurrency anomalies manifest even in simple coding tasks"; on a SWE-bench-style Django refactor a Write-After-Write collision is missed because "the plan assumes their write sets are disjoint … causing one to overwrite the other silently," and a Read-After-Write violation "surfaces only when" tests fail later even though "T2 ran after T0, yet the failure occurred regardless" — and "to our knowledge, no orchestrator tracks conflicts over state that spans all three scopes" (https://arxiv.org/abs/2610.03140).

**Signal B (Anchor 2):** *When Tool Calls Succeed but Workflows Fail: Anomalies at the Agent–Tool Boundary* (submitted 2026-09-14 as arXiv:2609.15397, cs.AI; artifact github.com/flame-stream/mcp-annotation-census) — eight recurring external-effect anomalies and "four points where black-box tool invocation alone cannot provide a general guarantee," measured "across 98,291 tools exposed by registered Model Context Protocol (MCP) servers" (registry snapshot 2026-07-27): annotation fields are "widely emitted but provide only coarse call-level hints, and none of the required capabilities is fully expressible" — `destructiveHint` is set on 65.8% of tools but applicable on just 12.9%, and only 3.1% assert an actual destructive operation. Its conclusion is that "the missing layer is therefore not another recovery mechanism, but reusable transactional contracts at the tool boundary" (https://arxiv.org/abs/2609.15397).

**Emergent Collision Point:** Each paper names half of one missing interface and stops. Paper B measures that the tool contract cannot state whether an effect occurred, can be compensated, staged or ordered — and concludes the answer is a contract at the tool boundary. Paper A shows the orchestrator cannot see which state each task read and wrote, spanning agent-local, orchestrator and external state — and proposes that external systems expose transactional interfaces to participate. Neither asks the question that falls out when you put them together: a contract at the tool boundary is useless unless the orchestrator records the footprint that makes the contract checkable, and a footprint is useless unless the contract declares what the effect means. The two halves are one artifact. That reframes the entire purchase decision: a durable-execution journal or an agent registry/gateway is provisioning a recorder and a directory for a transaction whose participants never agreed on a vocabulary — so the reliability infrastructure being bought in this window (the durable journal, the discovery plane, the MCP gateway) does not buy the property buyers think it buys.

**Hook:** The MCP registry's own metadata, measured across 98,291 tools, cannot say whether a tool can be undone — and the orchestrators calling those tools do not record which state the call touched. Two September–October papers, neither citing the other, describe the same missing object from opposite ends.

**Tension:** Agents in production write to systems of record every day, and the two mechanisms that are supposed to make that safe each assume the other is solved. The orchestrator's durable journal records *that a step ran*, not *what state it mutated*, so a parallel fan-out silently overwrites a sibling's write and the plan never notices. The tool interface records *that a call was made*, not whether the effect survived, can be reversed or must be ordered against a concurrent caller. Whoever is closest to the problem pays for both assumptions: an architect who buys durable execution gets replay against a model that cannot be replayed deterministically, and an architect who buys a gateway gets a single governed namespace for tools whose transactional semantics remain undeclared. Both halves of the boundary must carry the same object — the task's state footprint and the effect's meaning — and today neither side carries it.

**Target reader:** ai_architect (senior systems & protocol architect — distributed-systems literate, wants memory tiering topologies, MCP contracts, state recovery patterns, microservice RPC boundaries)

**Single claim to defend:** Making a multi-agent fabric reliable requires one artifact carried across the tool boundary — a task's state footprint plus the effect's declared semantics (occurrence, compensability, orderability) — and shipping either half alone (a durable-execution journal, or an MCP gateway/registry) cannot produce transactional guarantees, because the two halves are the same missing interface.
