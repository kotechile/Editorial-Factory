# Evergreen Brief: agentic_ai — 2026-10-19
**Archetype:** evergreen

**Persona:** ai_architect
**Decision the reader is facing:** How to shape the tool-call JSON schema an agent decodes against — which field comes first, which schema features are allowed, and which engine is trusted to compile it — so the constraint kills the malformed call without deleting the reasoning step that produced the answer, and what has to be tested before that schema ships in a runtime.
**Durability:** The mechanism is structural, not a model-version artifact: a constrained decoder masks tokens at generation time, so the schema's field order *is* the generation order, and a grammar engine that rejects a schema feature or under-constrains it fails silently at the boundary. Field order and engine coverage keep mattering in 12 months even as models change; every figure here is a dated snapshot a reader can re-check — the benchmark counts are **as of** arXiv:2501.10868v1 (JSONSchemaBench, 18 Jan 2025, revised 27 Feb 2025), the field-order measurement is **as of** arXiv:2408.02442v2 (Let Me Speak Freely?, 5 Aug 2024, revised 7 Oct 2024), and the schema size and enum caps are **as of** the OpenAI Structured Outputs guide retrieved 2026-10-19. What expires is a specific engine's coverage number and a specific provider's caps; the rule — test the schema against the engine, and put the reasoning field before the answer field — does not.
**De-dup:** `2026-10-19_your-tool-surface-is-a-release-surface` is this vertical's nearest prior artifact (published today, agentic_ai) — it treats the tool surface as an attack surface (injection through tool output, surface count as release scope), not as a decoder input, and carries no schema-ordering or grammar-coverage evidence. `2026-10-12_one-skill-too-many-green-test` is the nearer evergreen about green tests, but its subject is skill count and test blindness, not constrained decoding. Nearest *cross-vertical* neighbour checked and deliberately not re-argued: `2026-10-08_cache-boundary-decides-input-bill` (enterprise_ai_finops) owns prompt-caching layout in this corpus — a caching topic was drafted for this run and dropped as a retread (see candidates table), which is why this brief stays on the decode side of the same boundary.
**Thesis:** A tool schema is not a serialization detail but an instruction the decoder enforces token by token: in a benchmark of 9,558 real-world JSON schemas the best of six constrained-decoding frameworks covered twice as many as the worst, one popular engine accepted invalid instances in 38 test-suite categories while another failed to compile 37 of them, and a schema that puts `answer` before `reason` collapsed chain-of-thought in 100% of one model's JSON-mode responses — so the schema has to be ordered and tested like code, and a call that parses is not evidence that it reasoned.
