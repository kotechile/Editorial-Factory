# Evergreen Brief: gpu_hardware — 2026-11-11
**Archetype:** evergreen
**Vertical:** gpu_hardware
**Persona:** infra_engineer
**Decision the reader is facing:** You are serving a 9B-20B open-weight model on one card and must pick a quantization recipe — at the batch size and prompt length your traffic actually has, does 4-bit buy you throughput, or only capacity, and at what point does FP8 overtake it?
**Durability:** The mechanism is roofline arithmetic, not a part number: at batch 1 each generated token reads every weight once, so decode time is set by bytes moved and 4-bit weights move a quarter of BF16's bytes; at batch 256 one read of the weights serves 256 sequences, the matmuls become compute-bound, and W4A16 still computes in 16 bits. That is a property of transformer inference on any accelerator whose tensor cores run FP8 at twice the BF16 rate, so the rule survives the next silicon generation — what changes is the constant (Blackwell adds native NVFP4). Figures are as of: the compiled timing and accuracy record as of its literature cut-off 5 October 2026 (letter published 3 November 2026), the PyTorch GemLite/TorchAO throughput table as of that blog's own publication, the Gemma 3 12B INT4 checkpoint's numbers as of its model-card revision, and the H100 spec table as of the vendor page read 2026-11-11.
**De-dup:** `2026-11-04_seven-slices-89-percent-one-card` is this vertical's nearest prior evergreen artifact, and it argued how one card's memory, bandwidth, SMs and copy engines are divided between tenants (MIG profiles); this piece does not touch partitioning at all — it settles what number format the weights are stored in and shows that the rung's speedup is a function of batch size, not of the recipe's quality. Also differentiated: `2026-10-07_kv-cache-is-the-concurrency-ceiling` (the KV budget that caps sessions — the cache, never the weights), `2026-10-21_cap-your-card-at-80` (the power cap as an operating point), `2026-10-28_your-32-cards-spend-90-percent-talking` (the collective between cards), `2026-11-04_18x-lpddr-isnt-18tbs` (measurement bases for a bandwidth claim). Cross-vertical check run over the whole corpus: `grep -ril "quantiz|INT4|FP8|AWQ|GPTQ|4-bit" published/` returns only `2026-10-21_your-68k-tokens-cost-every-step` (int4 named once as a retained-state format for KV history), `2026-10-07_gpu-hour-price-set-by-memory` (quantization named in prose as a workaround for rental price) and `2026-10-06_fine-tune-vs-rent-by-token` (bitsandbytes 4-bit appears in a source list) — none argues the recipe-versus-operating-point mechanism, so the candidate is admitted by hand as well as by the gate.
**Thesis:** A quantization rung's speedup is the share of your step time that is memory-bound, not a property of the recipe — the same INT4 build is 1.95x to 2.12x faster than BF16 at batch 1, 1.16x at batch 32 and 1.02x at batch 256, while FP8 overtakes it exactly where the batch makes the matmul compute-bound; at that point four bits buys capacity (28 GB down to 10 GB) and a small accuracy bill, never throughput.

**Lead:** The vertical's own `primary_angles` ("inference economics", "memory bandwidth ceilings") crossed with `context/growth_os/founder-voice.md` §3's second pillar — "Deploying an 8B-14B quantized model running on commodity hardware at 100 tokens/sec beats calling a massive 400B frontier API for 80% of enterprise tasks" — which the desk has never tested in print, and with the same section's first pillar ("FLOPS are cheap; memory bandwidth ... the true gatekeeper"). The material is the arXiv intel feed: a November 2026 letter that compiled every public vLLM/SGLang timing and accuracy number in the 9B-20B band and found one rule that explains all of them, plus the PyTorch GemLite/TorchAO throughput table that is the primary source of its batch-size ladder, the shipped Gemma 3 12B INT4 checkpoint card, and the vendor spec table that prices the FP8 rate. `scripts/gsc_analyzer.py --vertical gpu_hardware` has returned no meaningful striking-distance demand on this vertical (impressions thin), so demand is a bonus signal and not the driver.
