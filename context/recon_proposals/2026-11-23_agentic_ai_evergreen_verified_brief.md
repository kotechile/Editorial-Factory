**Decision the reader is facing:** Which checks sit between the model and the tool before an external action is executed — whether a schema check, a deterministic gate (regex, set-membership, postcondition verify-before-retry) or a model judge is bought where, and how much of the harm and duplication each layer removes at what latency cost — when an agent is being wired to a system that cannot be rolled back.
**Durability:** The mechanism is structural and outlives any model generation: an agent emits an action, and the question of what inspects that action before it executes (program logic, a trained guardrail, or a judge) is an architecture decision, not a vendor feature. **Thesis:** The single most load-bearing layer in an agent runtime is the gate between the model and the tool: without it a shell-executing agent's realised-harm ceiling is 74.83%, and with the cheapest layer in the right place — a deterministic predicate in program logic, executed before the call — measured studies lift task success from 58% to 80%, cut realised harm from 74.83% to 37.33%, and reduce harmful tool invocations by 65%, all without spending the judge's token budget on checks a regex or set-membership test already answers.
