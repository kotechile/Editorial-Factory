# Evergreen Brief: multi_agent_enterprise_fabric — 2026-10-14

**Archetype:** evergreen

**Decision the reader is facing:** When a non-idempotent effect is gated on a parked agent workflow — a payment, a mail send, a requisition posted into SAP — do you rely on the framework's checkpoint/resume not to repeat the completed effect, or must the fabric own a consume-once claim in a shared store that outlives the pause? It bites the moment two workers answer the same interrupt (or one retry follows a lost response), and again when the pause runs longer than the effect layer's own dedupe window.
**Durability:** The mechanism is architectural, not a release artefact: a checkpoint records progress, never effect identity, so what "resume" means for work that already happened is a contract each persistence plane answers privately — a property of recovery design, not of any one version. The measured rates are as of the pinned releases the conformance study probed (LangGraph 1.2.9, LlamaIndex Workflows 2.22.2, CrewAI 1.15.2, pydantic-graph 1.107.1, AutoGen AgentChat 0.7.5; paper published 2026-08-04), and the study's own threats-to-validity section states individual violations may be patched upstream — which is exactly why the durable rule is not "framework X is broken" but "the effect must be claimed once in a store outside the run". The engine ceilings quoted are documented limits as of 2026-10-14 and move rarely; the key-retention figure is documented API behaviour as of 2026-10-14. A larger context window, a newer framework or a faster model changes none of it.
**De-dup:** `2026-10-07_durable-execution-not-a-transaction` is this vertical's nearest prior artifact (news, published 2026-10-07): its thesis is the tool *contract* between planner and gateway — the missing data footprint of a step and whether an effect is reversible — not what a persistence plane re-executes on resume, who may consume a parked approval, or how long an effect-layer key survives the pause. This piece carries a different rule (claim consumption once, in a store that outlives the run), a different figure set (consume-once saturation under concurrent resume, SF1/SF4 prevalence across five checkpoint/rollback systems, engine journal and pending-operation ceilings, idempotency-key retention) and shares no cited source with it. **Thesis:** Checkpointing licenses nothing about a completed effect: the resume plane has no shared contract, a parked interrupt answered by k processes fires the gated effect k times, and the effect layer's own idempotency key can be pruned in 24 hours — so the only durable fix is a consume-once claim, held in a store outside the execution, whose lifetime exceeds the pause.
