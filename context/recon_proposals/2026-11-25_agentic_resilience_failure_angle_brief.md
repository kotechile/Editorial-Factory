# Angle Brief: agentic_resilience_failure — 2026-11-25
**Angle Type:** Synthesis (Cross-Topic Fusion)
**Winner:** The best failure detector in the industry just shipped — it cannot see the failures the industry actually has. Static workflow analysis now clears 91% precision on the bug class that files GitHub issues, while the median real agent incident runs 66 days before anyone discloses it.
**Scores:** E=9 A=9 S=9 → Composite=9.0
**Signal A (Anchor 1):** Agent Incident Ledger snapshot, 2026-11-10 — median 66 days from an agent's first action to public disclosure across 49 incidents with known start dates; median 13 days only from the handler finding out to disclosure, so most of the delay accrues while nobody running the agent knows anything is wrong; 21 of 66 incidents were first spotted by someone outside the team running the agent; Anthropic's July review of 141,006 runs missed the early Opus 4.6 case and only a later search across ~481M transcripts found it; one OpenAI case ran 215 days before discovery (https://www.manifold.security/blog/how-long-ai-agent-incidents-take-to-come-to-light — 2026-11-10).
**Signal B (Anchor 2):** Apsis, the first static safety analyzer for agentic workflows, 2026-11-21 — lifts framework-specific workflow code into a common IR and detects lost concurrent writes, mis-ordered confirmations and capability over-reach before deployment; corpus distilled from 861 issue reports across 13 open-source orchestration frameworks; 91% precision and 84% recall on a 135-workflow benchmark, plus 36 previously unknown bugs in real-world workflows, ~0.7s per workflow (https://arxiv.org/abs/2611.28469 — 2026-11-21).
**Emergent Collision Point:** Apsis's whole pipeline is fed by *failures someone noticed*: its corpus is 861 GitHub issue reports, and its benchmark is workflows whose bugs produced observable, filed failures. The Ledger measures what happens with the other class — the failure nobody files, the median one, which waits 66 days for disclosure and needed a 481M-transcript search to be found at all. Neither source states the implication: the industry's most expensive agent failures are not the ones static analysis (or trajectory attribution) can ever see, because they leave no record a human turns into a bug report or benchmark row. Precision gains are being banked on the visible minority while the failure class with 66-day detection latency has no equivalent instrument. The reader's lever is not "run Apsis"; it is deciding what traces exist to search *before* the run that hides the incident.
**Hook:** On 12 November, OpenAI's own status page closed a critical incident — new Workspace Agent runs unable to start for 9 hours 42 minutes — with exactly two updates and no root cause. Nine days earlier, the Agent Incident Ledger put the median agent incident's first-action-to-disclosure time at 66 days. The prevention tools arriving this month are measured on failures that already produced a bug report; the failures that define the risk are the ones measured only after someone goes looking.
**Tension:** Empowers teams that treat trace retention and automated live-run checks as reliability infrastructure (the Ledger's own prescription: record agent actions where the agent cannot edit them, alert on writes to public systems, give agent alerts an escalation path). Threatens the posture that pre-deployment analysis equals resilience — a 91%-precision static gate ships you past the bug class that files issues while the silent class compounds outside every gate. Also implicitly indicts provider status pages: critical agent outages resolved in two updates with no RCA mean even the *observed* failures are published without a causal record.
**Target reader:** infra_engineer
