# Angle Brief: multi_agent_enterprise_fabric — 2026-10-21

**Angle Type:** Synthesis (Cross-Topic Fusion)
**Winner:** "Your agent fabric's bill has two meters, and only one is on the dashboard."
**Scores:** E=9 A=9 S=9 → Composite=9.0

**Signal A (Anchor 1):** "AgentLens: Framework-Aware Characterization and Resource Control for Heterogeneous LLM Agents" (Wentao Hong, arXiv:2610.25231, cs.OS; submitted 2026-10-18 — https://arxiv.org/abs/2610.25231). Ten agent frameworks on eleven matched SWE-rebench tasks, one dedicated host, inference remote so only orchestration cost lands on the box. Framework identity explains **52.95% of peak RSS variance**; task content explains **4.22%**. MetaGPT fires **117.2 execve events per tool call** against **3.0** in CAMEL — "a nearly 39x gap across frameworks performing the same abstract tool-use operation". Peak RSS and subprocess count correlate at **ρ=0.13**, so no single metric stands in for another. Under a co-located parent budget at 90% of aggregate peak demand, framework-aware cgroup coordination holds the protected worker's **P95 allocation latency at 5.7–7.1 ms** where static allocation inflates to **12.1–18.4 ms** and OOM-kill cascades kill two to three of every three repetitions.

**Signal B (Anchor 2):** "Which Model for Which Role? Cost-Efficient Pareto Recommendation for LLM Agentic Workflows" (Xie et al., arXiv:2610.26676; submitted 2026-10-19 — https://arxiv.org/abs/2610.26676). Model-per-role assignment as a search problem over **eight quality–cost matrices**, **two to five roles**, **up to 1,681 candidate assignments**. CC-Gittins recovers "a substantial fraction of the true Pareto frontier at **roughly 10% of the exhaustive-evaluation cost**", most of it by 30%; on BIRD Dev, "at **90% lower evaluation cost**… 88.75% mean recall and 100% mean precision over 20 seeds".

**Emergent Collision Point:** The two papers meter two different bills, and neither one meters the other's. Signal B prices the **token meter** — API spend per role — and shows the search for a good assignment is now cheap enough to run routinely. Signal A prices the **host meter** — memory, process churn, CPU — and shows that on identical work the harness you picked moves that meter by more than an order of magnitude relative to the task. Put them side by side and an enterprise fabric has two cost dials: one is measured down to the token, optimisable at 90% less search cost, and already the subject of a vendor product category ("govern every agent", "control AI spend"); the other is set at framework selection time, is decoupled from the metrics teams already watch (ρ=0.13), and has no line on the cost review. Neither paper says this. AgentLens never discusses model assignment; CC-Gittins never discusses host resources. The collision is that the industry's cost conversation — governance inventories and per-role routing — sits entirely on the meter that is already instrumented, while the meter that varies most per unit of work is the one nobody budgets from.

**Hook:** A 39x spread in kernel work per tool call between two frameworks running the same tasks, and a 90% cut in the cost of finding the cheapest model for each role — the first number never reaches the cost deck, the second is becoming a product feature.

**Tension:** Capacity planning for an agent fleet currently runs on task mix and model price list: pick the models, multiply by tokens, size the nodes. Signal A breaks the last step — the node envelope is a property of the harness, and the two axes teams use to forecast it (RSS and subprocess pressure) are nearly uncorrelated, so a budget built on one metric misses the other by construction. Meanwhile the vendor response to agent spend in this window is governance-shaped: MuleSoft's own calendar frames the problem as "Control AI Costs & Govern Every Agent" (2026-10-07) and "Controlling AI Spend While Navigating Regulatory Guardrails" (2026-11-18), i.e. visibility and policy over an inventory of agents. That is a real control — but it is a control over *who may spend*, not over *what the harness costs to run*. The teams that get hurt are the ones consolidating several frameworks onto one shared host budget; the teams that get helped are the ones that can fingerprint their harness and coordinate memory by phase.

**Target reader:** `ai_architect` (persona wants memory tiering topologies, MCP contracts, state recovery patterns, RPC boundaries).

**Single claim to defend:** An enterprise agent fabric's running cost is set as much by harness and host behaviour as by which model it calls in each role — and only the model-choice meter is instrumented, tooled and sold.
