**Signal B (Anchor 2):** Salt Security shipped Autonomous Defense on 2026-10-28 — workflows that revoke agent/MCP tool access, push blocking rules to WAFs and API gateways and reinstate guardrail policies — because, by its own 383-practitioner survey, only 17.5% of organizations can automatically stop an agent misbehaving in production and 49.8% had a confirmed or suspected agent action nobody authorized in the past year (https://salt.security/blog/an-alert-doesnt-stop-an-attack-introducing-autonomous-defense)
**Emergent Collision Point:** In the same 26 days the industry standardized *who an agent is* (DNS-anchored names, an 11-vendor registry, auditable public logs) while its own field data shows almost nobody can stop *what an agent is doing* (82.5% cannot auto-contain it; half have already taken an unauthorized action they did not catch). Neither source says this: ANS's seven documents describe naming, publication and monitoring — none of them is a containment control, and the Salt launch sells the brake the identity layer does not include. The control plane is filling in the order the RFCs arrive: identity first, fence last.
**Hook:** On November 10 the Linux Foundation gave every AI agent a way to prove who it is — seven spec documents, DNS-anchored, eleven vendors behind it. Twelve days earlier Salt Security shipped a product whose entire premise is that 82.5% of enterprises cannot stop the agent once it misbehaves.
**Tension:** Who this empowers: the standards bodies and identity vendors (Cisco, DigiCert, Salesforce) building the laminated ID cards. Who this threatens: the CAIO/CISO buying the registry as if a verifiable name were a control — an agent you can authenticate is not an agent you can stop, and the authorization layer ANS deliberately does not carry is the one the survey shows is missing (Salt: only 12.5% can trace a full agent path; more than 60% need hours or days to reconstruct yesterday).
