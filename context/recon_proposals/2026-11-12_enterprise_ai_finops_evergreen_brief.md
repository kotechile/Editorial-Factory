**Thesis:** Context length is a price tier, not a capability: past a schedule's threshold every token in the request — the answer and the cached reads included — is repriced (2× on Gemini 3.1 Pro's 200K boundary, 5× on Claude Haiku 5.5's 100,000-token step), so the tokens a team trims just above the cliff are worth several times the ones it trims anywhere else, and the cheaper model at 50K tokens can be the dearer one at 250K.

## Notes for the fact_check and drafting stages

1. **The cliff is a clause, not a table cell.** The column headers carry it (`Price (/1M tokens) <= 200K input tokens` beside `> 200K input tokens`), and the footnote states the consequence in one sentence: "If a query input context is longer than 200K tokens, all tokens (input and output) are charged at long context rates." That footnote cannot carry a gate row — a `200K`-led cell evidenced on "< 200 response code" earlier on the page — so it is quoted in `## Sources` under the verified row 1 and the article must attribute it to that page in the sentence.
2. **Arithmetic the article performs visibly (recompute in the final, never copy from this brief).** At Gemini 3.1 Pro Preview rates, a 200,000-token prompt with a 5,000-token answer costs 200,000 × $3.60/M + 5,000 × $21.60/M = $0.720 + $0.108 = $0.828. At 200,001 tokens the whole request moves to the long-context column: 200,001 × $7.20/M + 5,000 × $32.40/M = $1.440 + $0.162 = $1.602 — one extra token adds $0.774. Trimming a 250,000-token request to 190,000 cuts the input side from $1.800 to $0.684 (−62% of the input bill for −24% of the tokens). On Haiku 5.5, 100,000 tokens of input cost $0.010 and 100,001 cost $0.050.
3. **Do not call the Gemini row a "doubling of the bill".** Input doubles ($3.60 → $7.20) and cached input doubles ($0.36 → $0.72), but output rises 1.5× ($21.60 → $32.40). State each line separately; the total-request multiplier depends on the reader's input:output mix.
4. **The Claude leg is a step, not a cliff of the same size.** Haiku 5.5's 100,000-token step is 5× on the input rate ($0.10 → $0.50), while Claude 4.6 and later bill the full 1M window at the standard rate. The honest sentence is that the schedule, not the vendor, decides whether long context is a premium — so the model ranking at 250K tokens is not the ranking at 50K.
5. **The measured leg is dated.** RULER's finding ("only half … can maintain satisfactory performance at the length of 32K") is about 17 models evaluated in 2024; the article says so in the sentence and tells the reader to run the check on their own documents rather than treating it as a 2026 benchmark. It is the reason not to buy context you cannot use, not a claim that any current model is bad.
6. **Sources count:** three hosts — cloud.google.com, docs.claude.com, arxiv.org — all fetched on 2026-11-12. `finops.org/framework/capabilities/rate-optimization/` fetches and is useful for the framing ("commitment discounts are not resources … they are similar to coupons") but states no figure, so it can be cited in `## Sources` and prose only, never as a row.
