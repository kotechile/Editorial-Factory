# Angle Brief: agentic_resilience_failure — 2026-11-18
**Angle Type:** Synthesis (Cross-Topic Fusion)
**Winner:** "Your Transcript Says Done: 45% to 28%" — a success receipt attached to a step that never landed cuts an agent's whole-task success by 17 points, while a truthful note beside the same preserved error raises recovery by 15, and the same error moved out of a buried tool message into a runtime note is worth another 10.5 to 14.2 points — so the transcript is a control surface with two independent knobs and a sign that flips on whether the world matches the words.
**Scores:** E=8.8 A=9.0 S=8.7 → Composite=8.8
**Signal A (Anchor 1):** *Cleaning an Agent's History Hurts When the World Still Holds the Error* — arXiv:2611.14654, published **2026-11-10**. Freeze an agent with its exact world state, edit only its transcript, and let a receiver model continue. On AgentCE-Bench, after the agent commits a wrong value, a **truthful note beside the preserved error raises recovery from 51% to 66%** (+15.20 pp against a neutral note matched in role, placement, turn count and length), while **the same correct value recorded as the agent's own completed action lands below the unedited record, 50% to 44%** (−6.43 pp) — the gap between those two edits is **+21.63 pp [18.21, 25.08]**, the pre-registered headline over **319 tasks, 638 pairs**. On AppWorld, a **success receipt on a database write whose effect is absent cuts whole-task success from 45% to 28%**; the same receipt once the effect is present **raises it from 38% to 49%** — a **27-point interaction**, positive in six of eight receivers at 97.5% and seven at 95% (gpt-4o-mini unresolved). A record that only acknowledges the failure is unresolved at −2.50 pp [−5.08, 0.00]. (https://arxiv.org/abs/2611.14654)
**Signal B (Anchor 2):** *Same Error, Different Recovery: How Delivery Changes LLM Agent Behavior* — arXiv:2611.11581, published **2026-11-08**. Content held fixed, delivery varied, two studies fixed before data collection across 13 open models from 3B to 70B (60 scenarios, three error kinds, four forms, 720 conversations per model, local hash records). In the client's plain tool message, **five of six 7–35B models corrected a fixable error in only 2%–80% of cases** and **Llama-3.1-8B repeated a transient error in 98% of them**; moving the same error into a runtime note made those five act correctly almost always, and removing the failed exchange produced a "severe stopping failure" in the Llama models. Implemented as an opt-in recovery layer inside a deterministic inference engine it adds **+14.2 points** on explicit errors at 7–8B and **+10.5 points** at 32–70B on ToolMaze — and shows **no measurable gain** on 24 Loud/Quiet tasks whose corruption is silent. (https://arxiv.org/abs/2611.11581)
**Emergent Collision Point:** The two papers cut the same object — the trajectory an agent reads after a failure — along orthogonal axes, and neither tests the other's variable. Paper A varies **what the record asserts about the world** at a fixed world, and the sign of the effect flips: the identical correct value helps as a note beside the error and *hurts* as a completed action, and a success receipt helps or hurts by 27 points depending only on whether the write landed. Paper B varies **where the failure sits** at fixed content, and placement alone moves the next action from "corrects 2–80% of fixable errors" to "almost always". Put together, they say the transcript has two knobs, that the placement fix pays only when the assertion is true, and that a team which compacts a trajectory for token budget is turning the first knob with no test — the exact configuration paper A measures at −6.43 pp against doing nothing. The library that paper B ships is a *delivery* layer; wired over a history in which an earlier step has been rewritten as done, it is delivering a receipt, not a failure.
**Hook:** A database write goes through and the receipt says success, but the effect is absent — hand that history to the next agent and its whole-task success falls from 45% to 28%; put the same correct value in a note beside the preserved error instead and recovery climbs from 51% to 66%, a 21-point gap between two edits that disclose exactly the same number.
**Tension:** Who this helps: the team that owns compaction, handoff and retry-layer code, because each is a measurable change with a sign, and the cheap moves — keep the error, append the correction, move the failure out of the tool message — are worth 15 to 21 points at the cost of a few tokens. Who this hurts: anyone whose context budget is set by a token ceiling and whose postmortem tooling is built to produce a *clean* trace, because "clean" is the operation that measurably makes the next agent worse; and the recovery-layer vendor whose layer assumes the history it receives is honest. The limit is as important as the finding: better delivery buys nothing on silent corruption (no measurable gain on Loud/Quiet), and a record that merely acknowledges the failure is unresolved — so the rule is not "surface errors", it is "surface errors *and* the world state, never the claimed completion".
**Target reader:** infra_engineer
**Single claim to defend:** A tool-using agent's transcript is a control input to its next decision, with two independent measured variables — what it asserts about the world and where the failure sits — and only a truthful assertion plus a surfaced failure pays (+15.20 pp for the note, +10.5 to +14.2 pp for moving the error), while a claimed completion over an unfixed world costs 17 points, so compaction, handoff and recovery layers are production changes that need a sign test rather than token-budget hygiene.
